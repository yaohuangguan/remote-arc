# Remote Arc 0.5.1 parity benchmark — 2026-10-09

Hardware: Intel MacBook Pro i5-8279U, macOS 15.7.7, Node 24, Go 1.26.
Both engines built from the same PR #116 worktree after durability-profile
alignment and TS concurrency locking. Local JSONL IPC; production Cloudflare
Relay latency is deliberately excluded.

| Profile | Metric | TypeScript | Go |
|---|---|---:|---:|
| atomic | write_file P50 / P95 / P99 | 11.067 / 20.567 / 27.152 ms | 3.362 / 4.586 / 14.858 ms |
| atomic | undo_last_change P50 / P95 / P99 | 16.138 / 36.824 / 56.947 ms | 6.241 / 12.357 / 15.512 ms |
| durable | write_file P50 / P95 / P99 | 206.348 / 226.383 / 243.425 ms | 195.405 / 212.220 / 230.336 ms |
| durable | undo_last_change P50 / P95 / P99 | 64.744 / 79.101 / 94.937 ms | 52.554 / 62.480 / 71.744 ms |
| durable | read_file P50 / P95 / P99 | 0.987 / 1.594 / 2.301 ms | 0.291 / 0.389 / 0.746 ms |
| durable | read_file throughput, concurrency 32 | 3,125 req/s | 11,030 req/s |
| durable | RSS after workload | 74.51 MB | 11.79 MB |
| durable | CPU time after workload | 8.12 s | 2.79 s |

Tests included metadata reads, directory listing, 64 KiB binary reads, write,
edit, Undo with correctness checks, command execution, workspace-denied writes
and concurrent reads (1/8/32).

P95 and P99 use only 48 write/Undo samples each. Their tail statistics are
exploratory, not production SLO evidence. Read samples: 180; concurrent reads:
192 per concurrency setting.

45-second idle residency: Go remained 11.79 MB RSS and TS remained 74.51 MB;
both were alive. This is **not** a multi-hour leak or power-state test.

Crash/power-loss notes:
- `atomic`: temp-write + rename, no explicit fsync; not power-loss durable.
- `durable`: sync file before rename + parent directory sync on macOS/Linux;
  staged Undo also synchronizes metadata and original data.
- On Windows parent-directory syncing is currently unavailable (best effort).
- Crash after target write and before completed Undo manifest: automatic Undo
  refuses the prepared record. Manual inspection may be required.
- Append is not an atomic replacement. Tests must not imply that guarantee.
- No physical sudden-power-loss experiment was performed.
- New durability checks introduce additional I/O compared with the older,
  weaker contract, so comparing raw historic timings would be misleading.
