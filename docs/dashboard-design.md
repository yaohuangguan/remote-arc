# Dashboard 使用与设计说明

Dashboard 是任务与设备的观察、控制入口。用户日常仍从 AI 聊天提出需求，AI
在已有授权内直接调用工具，或为持续/定时工作创建持久任务。手动任务表单是
可选入口；不要求用户为每次文件或命令操作填写表单。

## 信息顺序

- 概览先显示在线设备、活动任务与需要处理的问题，再提供连接 AI、配对和安全入口。
- 任务页突出新建、搜索、状态筛选；等待 AI、设备离线与失败任务优先排列。
- 等待外部事件与等待源 AI 决策分别显示。源 AI 停止后，保存任务不等于继续推理。
- 每个任务展开显示规划轮次、决策摘要、完成证据与最近执行结果；执行记录只在
  展开时读取，并在关闭/切页时停止刷新。
- 每台设备单独控制任务能力；后台登录自启、源 AI 续接和防止闲置睡眠分别解释。
- 手机任务页优先保留活动/待处理统计；六个导航入口保持一行，详情不挤压任务正文。

## 阅读与操作尺度

主要正文/输入使用 16px，任务标题 17px，辅助内容 14px，紧凑标记 12–13px。
页面标题 28–36px、区块标题 22px。主要按钮至少 44px 高，任务权限开关有
可点击的完整标签、键盘焦点与禁用状态。两种语言及明暗主题共用同一结构。

实现位于 `apps/ui/src/dashboard.css`、`dashboard-task-view.tsx` 及现有
`main.tsx`。样式只作用于 Dashboard，保留官网及 Cloudflare 部署结构；
长任务 Docs 单独加载，避免给官网首页增加不必要的文档代码。

## 参考与选择

参考 IBM Carbon 官方的 [数据表使用规范](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)：
把搜索、筛选、主要动作放在列表工具栏，并通过展开逐步展示详细信息。Remote Arc
采用可展开任务行，手机转换为卡片结构；没有额外引入组件库。

参考 Carbon 的 [空状态规范](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)：
没有任务时说明下一步；搜索无结果时提供清除筛选；加载失败时保留已有信息并
提供重试。文字尺度和手机导航是针对本产品与用户反馈作出的具体选择。

## 验证范围

使用本地 `VITE_UI_PREVIEW=1` 的只读模拟数据检查桌面/手机、中文/英文、明暗
主题、搜索与筛选、源 AI 等待状态、证据/执行输出、设备权限以及新任务表单。
Preview 不连接生产 OAuth、D1、MCP 或设备。真实授权后的写入由 Relay 测试
覆盖，真实 Chat/Work 过夜验收仍单独列为待完成工作。
